## 3. 선정한 동시성과 근거

**선정: CONCURRENCY=10**

근거:
1. C=4: 14.8초/p — 안정적이나 Worker 10개 중 4개만 활용
2. C=6: 14.6초/p — C=4와 wall 차이 미미 (폴링 병목)
3. C=10: 8.6초/p — **1.7배 추가 개선**, 502/429 없음, 성공률 100%
4. Ollama Cloud: 10병렬에서도 429 미발생 (사실상 무제한)
5. Celery Worker 10개 = 동시성 10과 1:1 매칭

## 7. 잡다한 발견

1. **Docker 미사용 데이터**: 56GB 중 24GB 회수 가능 — 정리 후 25GB 여유 확보
2. **동시성 6에서 502 발생**: 디스크 4GB 미만 시 Docker 성능 저하로 API 응답 불가 → 디스크 가드 필수
3. **특정 페이지 반복 실패**: `금전출납부 2000 복지자금_2000_p23` — 특정 PDF 내용 자체 문제 (인덱싱 반복 실패). 고정 결함으로 분류.
4. **기처리 인식 불일치**: 전체 모드에서 서류철 경로 변화로 일부 키가 재확인됨 → 서버측 확인으로 안전하게 처리
5. **POLL_INTERVAL 영향**: 3초 vs 5초는 wall 시간에 직접 영향 (평균 1~2회 폴링 × 2초 절감 = 2~4초/페이지)
6. **Worker 10 메모리**: 443MB로 안정. 15.67GB 한도 대비 3% 사용.
7. **이미지 크기 실측**: 평균 226KB (168~243KB 범위), 목표 250KB 이하 달성
