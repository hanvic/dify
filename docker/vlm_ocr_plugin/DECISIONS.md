# VLM OCR Plugin - 자율 결정 기록

VLM OCR plugin 구축 과정에서 메인 에이전트가 자율적으로 내린 결정을 기록합니다.

## 결정 사항

| # | 결정 | 근거 | 날짜 |
|---|------|------|------|
| 1 | Dify Tool Plugin 아키텍처 사용 (코어 코드 수정 대신) | 업스트림 충돌 방지, VLM 전처리 관심사 분리가 명확함. | 2026-07-17 |
| 2 | 주요 이미지 형식으로 JPEG, PNG 지원 | 기업 문서 스캔의 대부분을 커버; 다른 형식은 추후 요청 시 추가. | 2026-07-17 |
| 3 | 큰 이미지는 A4 가독 가능 수준으로 리사이즈 | VLM 토큰/컨텍스트 제한 때문; 구체적 크기는 구현 서브에이전트가 선정. | 2026-07-17 |
| 4 | 모든 구현 작업을 서브에이전트에 위임하고 plan-eng-review로 게이트 리뷰 | 사용자가 요청한 subagent 기반 워크플로우. | 2026-07-17 |
| 5 | 구현 서브에이전트 모델로 `opus` 사용 | plugin SDK, Ollama 연동, Dify 내부 동작 파악에 고급 추론이 필요함. | 2026-07-17 |
| 6 | VLM 모델 기본값을 `qwen3.5:397b-cloud`로 유지 | 사용자가 `ollama run qwen3.5:cloud`로 이미지 질의 시 정상 응답을 확인. `/api/chat` 직접 호출의 500 오류는 요청 형식 문제일 가능성이 높음. | 2026-07-17 |
| 7 | 모델명/URL은 plugin credentials에서 변경 가능하게 설정 | 모델별 요청 형식과 가용성이 다르므로 운영 환경에 따라 교체 가능해야 함. | 2026-07-17 |
| 8 | 구현 서브에이전트는 가벼운 모델, plan-eng-review는 고급 모델 + xhigh 사용 | 사용자 요청에 따라 리소스 효율성과 리뷰 품질 균형. | 2026-07-17 |
| 9 | 이미지 다운로드 SSRF 보호 수준 결정 | Dify `File.url`은 signed URL로 Dify API 서버만 가리킴. 완벽한 DNS rebinding 대응 대신 연결 후 실제 IP 검증 방식으로 탐지, 스킴/리터럴 IP/리다이렉트 차단은 유지. | 2026-07-17 |
| 10 | plugin daemon에 unsigned local plugin 설치를 위해 `FORCE_VERIFYING_SIGNATURE=false`로 설정 | daemon이 `verify_signature=false` 요청을 무시하고 강제 서명 검증을 해서 unsigned local package 설치가 불가능했음. 로컬 개발/검증 목적으로만 적용, 운영 환경에서는 적절한 보안 정책 적용 필요. | 2026-07-17 |
